## Design

Read `docs/DESIGN_BRIEF.md` before changing any frontend file; section 12 records where the build differs from the brief and why. In short: paper page with black photographic bands, Archivo and IBM Plex Mono, hairline rules and rows (no cards, shadows, gradients or rounded corners), one orange word per page. Only Mat Harvey is named anywhere on the site. Copy rules: plain voice, no em dashes, no hype words, no invented reviews, ratings or results.

## Project Overview

The Bodyweight Gym Online is a fully static site (GitHub Pages, thebodyweightgym.org). It sells the two Bodyweight Skills books (Amazon links only) and gives away the gym's 2020 live-streamed classes as YouTube embeds. There is no backend; see `README.md` for deploy steps.

## Architecture

- **public/**: the deployed site root. Pages: `index.html`, `classes.html` (`/classes`), `video.html` (`/video?id=`), `blog/index.html`, `blog/post.html` (`/blog/post?slug=`), `books/` (`/books`, `/books/handstand`, `/books/ring-muscle-up`), `ebook.html` (redirect to `/books`), `404.html` (also redirects old `/blog/<slug>` links), `offline.html`.
- **Generated regions:** `scripts/build-pages.js` (part of `npm run build`, Node built-ins only) writes `src/partials/{head,nav,footer}.html` into every page between `<!-- build:NAME -->` markers, pre-renders the featured classes, the `/classes` library and the blog lists, and fills `<span data-stat="...">` numbers. Edit the partials or the script, never the generated regions by hand.
- **public/data/videos.json**: hand-edited video database. `categories.json`, `instructors.json`, `blogs.json` are generated by `scripts/build-data.js`. Only videos with a real 11-character `youtubeId` are listed or counted.
- **scripts/blog-meta.json**: which blog posts are published, their order and card metadata.
- **public/css/brand.css**: the only stylesheet.
- **JS:** `public/js/data.js` (`window.BWG`: JSON loading, favourites in `localStorage`), `site.js` (menu, scroll reveal, hero parallax, click-to-play YouTube), `classes.js` (filters, search, sort, saved), `video.js`, `post.js` (renders markdown with `marked`), `books-config.js` + `books.js` (Amazon buttons, signup, buy bar).
- **Books:** Amazon URLs and the signup option live only in `public/js/books-config.js`; a `TODO_...` value renders a disabled "coming soon" label, never a link. Book pages keep their Book JSON-LD and OG tags. No book text, PDFs or EPUBs in the repo (KDP terms).
- **Images:** `npm run images` (`scripts/build-images.js`, needs `npm install` for sharp) builds `public/images/{photos,books,classes,demos,blog,brand}` and `public/icons/` from `assets/` and YouTube frames, through the colour grade in `scripts/lib/grade.js`. Outputs are committed. `node scripts/build-images.js classes demos` runs single steps (brand, photos, covers, classes, demos, blog).
- **Base path:** the live site may be served from `<owner>.github.io/<repo>/` before the custom domain is set. HTML keeps root-based URLs and `scripts/prepare-pages.js` (run by the Pages workflow) prefixes them in the deployed copy, using the `base_path` GitHub reports. Scripts must build URLs with `BWG.url('/path')` (`window.BWG_BASE` is defined in the head partial and set at deploy), never a bare `'/path'`. Pages that run before `data.js` read `window.BWG_BASE` directly.
- Do not add `/api/*` calls; everything is fetched from static files.

## Common Commands

```bash
npm run build                    # regenerate public/data/*.json and the generated page regions
npm start                        # preview with npx serve public
npm run images                   # rebuild all graded images (needs npm install for sharp)
node scripts/build-images.js classes   # one step only
npm run thumbnails               # legacy FFmpeg thumbnails (needs local video files)
node analyze-video-start-times.js      # detect start times
node update-video-database.js          # merge start times into videos.json
```

## Video Data

Each entry in `public/data/videos.json`:
```javascript
{
  id, title, instructor, duration, level, category, equipment,
  description, thumbnail, filename, youtubeId, views, rating,
  startTime, startTimeFormatted
}
```
`youtubeId` is the 11-character YouTube ID (`"TODO"` until known). `title` keeps the original "Coach X - ..." form; the site shows only the part after the dash. `views` is refreshed from YouTube by `npm run build` when `YOUTUBE_API_KEY` is set; `/classes` sorts by views or duration (`rating` is unused placeholder data). `startTime` (seconds) is passed to the embed to skip intros.

## Adding New Videos
1. Add an entry to `public/data/videos.json` with the `youtubeId`.
2. `npm run images` (or `node scripts/build-images.js classes`) to fetch and grade its frame; check it is clear of stream overlays and adjust `FRAME_CROP_FOR` / `FRAME_PICK` if not.
3. `npm run build`, then commit `public/`.
